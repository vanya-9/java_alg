# 🗂 Хэш-таблицы и множества (4 задачи)
Подсчёт, дедупликация и быстрый поиск через хэш-таблицы и множества.

## 🟢 Уровень 1: Разминка и базовые паттерны

### 2. Удалить лишние повторения из массива
**Теги:** `#хэш-таблица` `#массивы`
**Условие:** Дан массив, необходимо оставить только N повторений каждого числа, сохранив исходный порядок элементов.
**Что требуется:** Решение за O(N) по времени с использованием O(N) дополнительной памяти. 
**Где ошибаются:** Пишут квадратичные решения (O(N²)); портят исходный порядок элементов при фильтрации.

## 🟡 Уровень 2: Золотой стандарт собеседований

### 3. Пересечение топов двух выдач
**Теги:** `#хэш-таблица` `#множества` `#массивы`
**Условие:** Для двух массивов целых чисел (DocId) длины N, для всех K от 1 до N нужно посчитать количество общих документов в топах (префиксах) размера K. Числа в пределах массива могут повторяться.
**Примеры:** 
- *Без учета кратности:* `CountCommon({1, 1, 2, 3}, {2, 1, 3, 1})` → `[0, 1, 2, 3]`
- *С учетом кратности:* `CountCommon({1, 1, 1, 1}, {1, 2, 1, 4})` → `[1, 1, 2, 2]`
**Что требуется:** Решение за линейное время с двумя хэш-сетами (или хэш-мапами для варианта с кратностью) для левой и правой выдачи. 
**Где ошибаются:** Не уточняют про повторы внутри одного вектора (важно задать этот вопрос интервьюеру!); делают квадратичный подсчёт по всем префиксам вместо накопительного.

### 4. Вертикальная ось симметрии
**Теги:** `#хэш-таблица` `#геометрия` `#краевые-случаи`
**Условие:** Дан массив точек с целочисленными координатами (x, y). Определить, существует ли вертикальная прямая, делящая все точки на 2 симметричных относительно этой прямой набора.
**Примеры:** 
- `isVertSym([[0,0], [1,1], [2,2], [3,1], [4,1], [4,0]])` → `true`
- `isVertSym([[0,0], [10,0]])` → `true`
- `isVertSym([[0,0], [11,1]])` → `false`
**Что требуется:** Решение за O(N) через хэш-таблицу. 
1. Найти min/max X за O(N). 
2. Из min/max получить ось симметрии. 
3. Положить все точки в хэш-сет. 
4. Пройтись по точкам и проверить наличие симметричной пары.
**Где ошибаются:** Пишут решения за O(N log N) (через сортировку); ошибаются в точности оси (чтобы избежать дробных чисел, лучше хранить удвоенную координату `min_x + max_x`); забывают про дубликаты точек, точки на самой оси и переполнение `int` при сложении координат.

## 🔴 Уровень 3: Продвинутое моделирование и откаты

### 1. Оптимизация маршрута (удаление петель)
**Теги:** `#хэш-таблица` `#множества` `#моделирование` `#сетка`
**Условие:** Дан список направлений (L, R, U, D). Каждое направление перемещает нас на 1 шаг. Петли (возврат в уже посещенную точку) дают нулевое перемещение. Нужно удалить из списка все петли и вернуть оптимизированный короткий маршрут.
**Примеры:** 
- `[R, D, L, U, R]` → `[R]`
- `[R, D, L, R, U, U, R]` → `[R, U, R]`
- `[D, R, U]` → `[D, R, U]` (цель не просто попасть в точку, а придерживаться маршрута)
**Что требуется:** Решение за O(N) по времени и O(N) по памяти. 
Идея: использовать хэш-сет с посещёнными координатами и список (вектор) пройденных шагов. Как только видим, что текущая координата уже есть в хэш-сете (обнаружили петлю), отступаем по списку шагов назад, удаляя шаги и попутно очищая хэш-сет от этих координат.
**Где ошибаются:** 
1. Пытаются просто удалять куски массива, но забывают очищать хэш-мапу в процессе вырезания (что приводит к неверным срабатываниям в будущем).
2. **Критический подводный камень:** если финальная точка маршрута находится на петле, то в хэш-мапе направлений для неё будет записано "куда идти дальше", а ведь дальше идти не надо. Это упускают почти все кандидаты.
